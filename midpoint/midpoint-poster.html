Fuzzy Cache Lookups for Partially Stateful Tool Calls

Harshaan Chugh, Kevin Rodriguez, Etienne Sasenarine, Rohan Shankar  ·  Advisor: Bhaskar Kataria
Cornell University  ·  Team 30  ·  Midpoint, November 2026
When an agent repeats a tool call in a different state, can we safely reuse the old result?

Motivation

Agentic RL samples many rollouts per task, and they repeat tool calls. TVCache [1] reuses a result only if the call and every earlier state-changing call match exactly, so it misses respelled queries and reads after unrelated writes.

Approach

  1. Canonicalize each call: SQL with SQLGlot [2]; cat, ls, echo, cd with absolute paths.
  2. Find the state it reads and writes: tables, files, the working directory.
  3. Version each piece of state by hashing the writes to it.
  4. Exact lookup first; on a miss, key a read by its canonical text and the versions of the state it reads.

Writes always execute; only reads are reused. Anything we can't analyze (pipes, random(), unknown commands) falls back to plain TVCache.

Evaluation setup

1,297 generated SQL and shell calls; every reused value is checked against real execution. Oracle: a perfect canonicalizer. Hints: read-only calls declared to TVCache.

Next steps

  • Terminal-bench rollouts on a Docker host, with per-command output.
  • Wider shell coverage and a state key for sqlite_master.
  • RL runs with verl; contribute the lookup to TVCache.
